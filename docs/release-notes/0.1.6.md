## 本版改了什么

这一版没有新功能，只做一件事：别人给的整合包和版本描述，不再能决定文件被写到哪儿；下载中途断掉，也不再被当成成功。

* **整合包里的路径能写到启动器目录之外**。`.mrpack` 的 `files[].path` 允许写成绝对路径（`D:/…`）、网络共享（`\\主机\共享\…`）、`..\..\` 或 `C:相对路径`，安装时照单全收，文件就落到数据目录、程序目录甚至系统盘的任意位置。现在这类条目会被拒绝，报「不是包内路径」，包里其余合法文件照常安装。
* **整合包的名字和版本号同样能越界**：包名写成 `../../别处`，版本目录就会建到数据目录外面。现在包名和版本会被规整成单个目录名，越界字符变成 `-`；正常整合包的名字不受影响。
* **版本清单（version json）里的库、资源索引、资源对象加了边界检查**：`downloads.artifact.path`、`assetIndex.path` 越界即失败；资源对象的哈希必须是 40 位十六进制才被当成目录名用，否则报错而不是拼出一个奇怪的目录。
* **下载被截断不再算成功**。服务器只发了一半就断开时，以前照样把截断的文件写到磁盘、报安装成功，等到启动游戏才莫名其妙地崩。现在核对「承诺多少字节 / 实际收到多少字节」，不一致就报 `network: the server sent N of M bytes`；多文件下载会重试两次，仍不行就把这次安装标成失败，磁盘上不会留下半个文件。
* **大文件不再被 30 秒总时长切断**。以前下载超过 30 秒就超时，慢速镜像或机械硬盘下几乎没下完过；现在只有连续 30 秒没有任何数据才算超时。
* **natives 不再每次启动都重新解包**：解包完在 `natives` 目录留一个标记，jar 没变就跳过；还顺带修了更糟的一种情况——解包失败也会留下标记，之后每次启动都跳过解包，带着残缺的 natives 去跑游戏。
* **展示和复制的命令行按 Windows 规则加引号**：Java 装在 `C:\Program Files\…` 这类带空格的路径下时，以前参数会被拆开。
* macOS 构建的平台名改成 Minecraft 清单认的 `osx`（本版仍只发 Windows，这一条是为将来的 macOS 包铺路）。

已有的实例不需要重装。行为上唯一能感觉到的是：被改坏的整合包或版本清单现在会直接安装失败，而不是装出一个「看着正常、启动就崩」的实例。
